# Pass List — Cardless, Software Engineer (Backend)

A broad, level-flexible backend IC role (mid-level through staff, calibrated at interview) whose real distinguishing bar is comfort operating in a regulated, money-moving environment, not any one specific language or framework.

## HR pass list

| # | Check | Where | What passes |
|---|---|---|---|
| 1 | Work authorization | Form | Answer on application (legally authorized to work in the US, no sponsorship needed) |
| 2 | Location | Form | Based in San Francisco or willing to relocate (relocation always passes per house rule) |
| 3 | Degree | Skim | Not a listed requirement; any degree or no degree is fine |
| 4 | Years in backend engineer roles | Skim | 2+ years in roles titled Software Engineer, Backend Engineer, or equivalent (open band, mid-level through staff; x.5 years counts as x+1) |
| 5 | Required tool / language | Skim | A modern backend language visible in a real role, e.g. Python, Java, Node.js, Go, C++ (Java is their stack but explicitly not required of candidates) |
| 6 | Regulated/high-stakes keyword | Skim | "Production," "real-time," or a regulated-domain word (healthcare, financial, compliance) near a backend project, signalling the distinguishing requirement |
| 7 | Salary expectation | Form | Answer on application; band is wide ($160k-$295k) so unlikely to filter most candidates |

Notes:
- The degree line is genuinely absent from this JD, unlike most postings; do not add a degree skim check beyond "not found = no issue."
- The $160k-$295k band is unusually wide (mid to staff), so overqualification is not a realistic skim filter here.

## Hiring manager pass list

| # | Check | What passes |
|---|---|---|
| 1 | Production backend service ownership | Built and operated a backend service end to end (scoping through production rollout), not just a feature add, using a real modern language/ecosystem |
| 2 | Distributed systems / API / database fundamentals | Named project showing API design, database work, and infrastructure deployment (not a Skills-list mention) |
| 3 | Regulated or high-stakes environment judgment | Worked on a system where correctness mattered materially (healthcare, financial, or other compliance-sensitive data), with a concrete example of handling that constraint |
| 4 | Cross-system / ambiguity-to-production ownership | Took a project from an ambiguous starting point through design, implementation, and rollout, ideally touching more than one service/domain |

**Likely fifth (borderline)**: external partner-facing API experience (H3) or reliability/observability work (H4). Most hiring managers will waive this if checks 1-4 are strong, since the JD frames it as something gained on the job rather than a hard bar.

Soft skills from the required section (systems thinking under incomplete information, clear communication, genuine care about correctness) sit on neither list; a CV cannot prove them, they are tested in interview.

## Not needed to pass either list

Fintech/payments/lending domain experience (N1), workflow orchestration or event streaming (N2), any specific framework beyond "a modern backend language," and any advanced degree.

## Ranking among passes

Among candidates who pass both gates, fintech/payments/lending/card-issuing experience (N1) ranks first since it is the company's core business and the JD says it weights this heavily. Workflow orchestration or event streaming (N2) ranks next. External partner-facing API work and reliability/observability ownership, even though waivable at the hiring-manager gate, still separate otherwise-similar candidates and should be weighed after N1/N2. A regulated-environment background outside fintech (e.g. healthcare) ranks above a generic SaaS background but below direct payments experience.
